# v3.1 — Multi-Agent Messaging Layer (Foundational)

This is the first implementation slice for DriftQ v3 messaging.

## Topic conventions

- `agent.{id}.inbox`
- `agent.{id}.outbox`
- `team.{id}.broadcast`

`{id}` should use only: letters, numbers, `_`, `-`.

## Agent message contract (JSON in `Message.Value`)

Required fields (minimum):

- `sender`
- `intent`
- `payload` (must be a JSON object)
- one route target:
  - `receiver` (direct)
  - `capability` or `role` (capability routing)
  - `team` (broadcast)

Optional fields included now so we do not need to retrofit later:

- `message_id`
- `correlation_id`
- `reply_to`
- `created_at`
- `tenant_id`
- `route` (`direct`, `capability`, `broadcast`) — optional, validated against inferred route

## Example: direct message

```json
{
  "message_id": "msg_001",
  "sender": "planner",
  "receiver": "coder",
  "intent": "implement_pr",
  "payload": {
    "repo": "DriftQ-Core",
    "pr": 1
  }
}
```

## Example: capability message

```json
{
  "sender": "planner",
  "capability": "coding",
  "intent": "implement_pr",
  "payload": {
    "repo": "DriftQ-Core",
    "pr": 1
  }
}
```

## Example: broadcast message

```json
{
  "sender": "coordinator",
  "team": "core",
  "intent": "announce",
  "payload": {
    "text": "Deployment starts in 5 minutes"
  }
}
```

## PR #2: capability registry + router (this patch)

Added `internal/multiagent/router.go` and `registry.go`:

- `CapabilityRegistry` (in-memory, round-robin per capability)
- `Router` implementing `broker.Router`
  - direct -> `agent.{receiver}.inbox`
  - capability/role -> registry lookup -> `agent.{selected}.inbox`
  - broadcast -> `team.{team}.broadcast`
- routing metadata added to `broker.Message.Routing.Meta` (route kind, sender, selected agent, etc.)

### Example registry setup (inside `driftqd` wiring later)

```go
reg := multiagent.NewCapabilityRegistry()
_ = reg.Register("coding", "coder-a", "coder-b")
_ = reg.Register("review", "reviewer")

r := multiagent.NewRouterWithRegistry(reg)
b.SetRouter(r)
```

> Note: if attached globally, the router defaults to **non-strict** mode so non-agent messages are ignored (no reroute).

## PR #3: driftqd startup config + topic bootstrap (this patch)

Added `internal/multiagent/config.go` and `cmd/driftqd` wiring so v3.1 can be enabled at startup without custom code edits.

### New driftqd flags

- `-multiagent-config=/path/to/multiagent.json`
- `-bootstrap-multiagent-topics`

### What the config supports right now

- `agents` (creates inbox + outbox topics)
- `teams` (creates team broadcast topics)
- `capabilities` (builds capability registry for router)
- `topic_partitions` (defaults to `1`)
- `router_strict`
- `source_topics` (optional router scope)

### Example config

```json
{
  "agents": ["planner"],
  "teams": ["core"],
  "capabilities": {
    "coding": ["coder-a", "coder-b"],
    "review": ["reviewer"]
  },
  "topic_partitions": 1,
  "router_strict": false,
  "source_topics": ["agent-ingress"]
}
```

### Example run

```bash
driftqd \
  -multiagent-config ./multiagent.json \
  -bootstrap-multiagent-topics
```

Notes:
- topic bootstrap is safe to rerun (`topic already exists` is treated as skip)
- if `-multiagent-config` is not provided, driftqd keeps the current `TestRouter` behavior
